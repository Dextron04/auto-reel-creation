# Local AI Reel Automation

Local 9:16 reel pipeline using n8n for orchestration and Remotion for rendering.

## Current milestone

The workflow researches current AI developer tools, creates a 30-second Peter–Stewie dialogue, generates both local voices, and renders a 1080×1920 reel with short word-highlighted subtitles. After script generation it collects relevant identity, interface, mechanism, and outcome images from product, documentation and article pages, supplemented by Wikimedia Commons image search. Peter and Stewie PNG cutouts switch with the active voice. A transparent PNG overlay remains optional.

## Run

1. Fill in `.env.prod` with your Anthropic API key, Cloudflare Access credentials, and TTS API key.
2. Place the source video at `media/source.mp4`.
3. Place optional voice audio and PNG overlay under `media/`.
4. Start with `docker compose up --build`.
5. Open n8n at http://localhost:5678 and import `n8n/workflows/research-and-render-reel.json`.
6. Run the workflow. Rendered files appear in `output/`.

The renderer health endpoint is http://localhost:3001/health. Platform publishing is intentionally not included yet.

## Research workflow

Import `n8n/workflows/research-and-render-reel.json` into n8n. The research trigger is configured for 09:00 and 17:00 in the n8n timezone. Before activating it, provide `ANTHROPIC_API_KEY`, `OLLAMA_CF_ACCESS_CLIENT_ID`, and `OLLAMA_CF_ACCESS_CLIENT_SECRET` to the n8n container environment, or replace the header expressions with n8n credentials.

The research stage combines 10 feeds from OpenAI, Google AI, Hugging Face, GitHub, DEV, Product Hunt, AWS, Vercel, and JetBrains. It deduplicates and scores releases for recency, developer relevance, source authority, cross-source momentum, and useful SEO terms before sending the top signals to Claude through Anthropic's Messages API. `ANTHROPIC_MODEL` defaults to the low-latency `claude-haiku-4-5-20251001`; set it to `claude-sonnet-5` if you prefer deeper synthesis. If Claude returns an HTTP error (including exhausted credits or rate limits), an Anthropic error payload, or empty output, the workflow automatically retries the same research prompt with local `tushin-agent:latest` at `https://ollama.dextron04.in/api/generate`.

The research model must return five evidence-backed candidates, one recommended topic, exact source URLs, and an SEO brief. Claude then writes six alternating Peter and Stewie turns totaling roughly 55–68 words; dialogue generation uses the same automatic local-Qwen fallback policy as research. Each turn is sent to the matching configured voice and saved separately. The renderer measures the actual WAV durations, sequences the dialogue without overlap, and gently accelerates it only when necessary to stay within 29.5 seconds.

Subtitle groups contain no more than four words. Peter's active word is yellow and Stewie's active word is red, while inactive words remain white. The script model plans 6–8 image cues, at least one per turn, each anchored to an exact spoken phrase with a purpose (identity, interface, mechanism, outcome) and a source page. The n8n node `Find and Download Script Images` calls the renderer's `/v1/visuals` collector. For each cue it gathers candidates from a web image search for the tool plus the cue query (Brave Search when `BRAVE_SEARCH_API_KEY` is set, otherwise keyless DuckDuckGo, which rate-limits bursts and is then skipped for that cue), matching images on the cue's source page and the research claim pages, screenshots and diagrams from a GitHub README when the source is a repository, and a rendering of the source page itself made with the container's headless Chromium (through a proxy that only allows public addresses) sliced into hero, middle and lower views. The best-ranked candidates are downloaded and validated, then Claude (vision, `ANTHROPIC_VISUAL_JUDGE_MODEL`, default `claude-haiku-4-5`, using the same `ANTHROPIC_API_KEY`) is shown the spoken line, the exact phrase and the intended purpose and must pick the one picture that clearly illustrates it or reject them all. A rejected cue gets no picture, and the previous relevant picture simply stays on screen; nothing generic is ever substituted. Without an API key the collector falls back to its heuristic ranking. Site icons are used only for identity cues, social cards only from the cue's own page, and the same underlying picture is never shown twice in a reel. Selections, the judge's reason, and every rejected candidate are recorded in `/media/visuals/<run>/manifest.json`. Each visual starts at its spoken phrase (or at the start of its turn) and stays on screen until the next cue, so a relevant picture is visible for the whole dialogue. Phrase timing uses the estimated caption tokens; it is not forced audio alignment. Web relevance and image rights still require editorial review. The collector does not use Google/Bing image search. Configure `TTS_PETER_VOICE` and `TTS_STEWIE_VOICE` (plus their optional reference IDs) in `.env.prod`. Human review is no longer required before publication for Instagram: after render, `Write Instagram Caption with Claude` drafts a short caption and 5-8 hashtags from the tool's hook, one-line value, the dialogue, and the existing SEO brief; if that call fails or returns unusable JSON, the caption falls back to the SEO brief's own description and hashtags. `Publish to Instagram` then calls the renderer's `/v1/publish/instagram`, which creates a Reels media container from the video (served publicly at `PUBLIC_MEDIA_BASE_URL` via the same Cloudflare Tunnel pattern used elsewhere), polls until Instagram finishes processing it, publishes it, and returns the permalink. Any failure in that chain — including a container error or a poll timeout — fails the run visibly rather than retrying or posting anything partial. Configure `INSTAGRAM_ACCESS_TOKEN`, `INSTAGRAM_BUSINESS_ACCOUNT_ID`, `INSTAGRAM_GRAPH_API_VERSION`, and `PUBLIC_MEDIA_BASE_URL` in `.env.prod`.
